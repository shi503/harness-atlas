**Context.** Skill triggering behaviour is easy to get wrong in a way that produces no error and no signal.

**Decision.** Triggering is the `description` field alone; there is no separate trigger-phrase field and inventing one silently degrades coverage. Descriptions are written as *what it does + when to use it*, ending in the literal phrases a user would say. `model` and `tools` are not skill-level fields — `model` belongs on an agent, tool restriction is `allowed-tools`. Every side-effecting skill — anything that writes, posts, publishes, or touches orchestration state — sets `disable-model-invocation: true` and remains explicitly invocable. Every skill carries a `## Gotchas` section of concrete failure points.

**Consequences.** Triggering is predictable, and destructive skills cannot fire on a passing mention.

**Failure of the simpler design.** The predecessor carried a non-existent trigger-phrase key in 16 skills. The harness never read it, so every one of them under-triggered with no visible symptom until an audit found it.

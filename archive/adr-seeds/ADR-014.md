**Context.** Polling a long-running agent's status is a hot path. Any model call in it costs tokens and latency on every check.

**Decision.** Heartbeats are append-only fenced JSON blocks. The checker extracts every block, parses the last, and alerts if `escalation_needed` is truthy **or if the block fails to parse**. Failure alerts rather than passes. The worker-side rule: on a block, set the blocked status, set escalation, and **stop** — do not guess around architectural ambiguity.

**Consequences.** Status checking is free and can run on any cadence. Malformed heartbeats surface instead of silently reading as healthy.

**Failure of the simpler design.** A model-parsed status check costs a call per poll, which makes frequent polling expensive and infrequent polling useless.

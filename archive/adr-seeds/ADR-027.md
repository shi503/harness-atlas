**Context.** Two independent instantiations of the same four-tier framework produced the same defect register: one flat state map shared across blueprints, no dependency edges represented in state, and an initialization command that silently resets everything. The predecessor logged it across five separate issues and left the remediation unimplemented; this repository logged it as its own ISSUE-002 with an operational warning to back up state first.

**Decision.** Retire the resolver. Dependency resolution, claiming and parallel dispatch move to the harness's native orchestration, which supplies task dependencies and file-locked claiming. The blueprint is retained as a **declaration** artifact — a reviewable statement of the graph — and the contracts in ADR-008 through ADR-013 are retained in full, because the harness supplies none of them.

**Consequences.** The defect class disappears with the code that caused it. Effort moves to the context function, which is the only one the harness is not building.

**Failure of the simpler design.** A flat status map cannot represent the dependency graph it is resolving; edges live in the blueprint and state holds only nodes. Every downstream symptom — unenforced contingency edges, destructive initialization, cross-blueprint collision, hand-patched JSON — follows from that single omission. It was found twice, by two teams, with no contact between the discoveries.

**Context.** Dispatch hands a worker a document and a fresh context window. Anything the author knew and did not write is lost.

**Decision.** Every PRD carries seven sections — overview with sources and decisions linked by ID, independently checkable acceptance criteria, a read/write file manifest, a runnable gate, a session protocol, explicit out-of-scope, and an appended blocker log. It carries an authoring note, deleted before dispatch, stating the contract: reference guides by path rather than pasting them, and link decisions by ID rather than restating them.

**Consequences.** Context cost per dispatch drops, because the PRD points rather than inlines. Ambiguity becomes visible at authoring time rather than at execution time.

**Failure of the simpler design.** A PRD written as prose by someone holding session context reads as complete to its author and is unexecutable by anyone else. The out-of-scope section in particular is load-bearing for a second reason: it is where the decomposition's seams become visible.

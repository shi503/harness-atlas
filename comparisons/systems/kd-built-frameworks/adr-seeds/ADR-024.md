**Context.** Capabilities are authored in a hub that contains guides, standards and references, and installed into repositories that contain none of them.

**Decision.** A distributed skill inlines its own checklist and cites the canonical guide **by name**, never by hub-relative path. Hub-internal documents may link freely. The distribution model states explicitly which channels reach a sibling repository — a walk-up reference and a package install — and **names what neither channel can deliver**.

**Consequences.** A skill degrades visibly rather than silently when a reference is missing, and the reachability boundary is written down instead of assumed.

**Failure of the simpler design.** This is recorded from an incident: a review skill was promoted to team-wide distribution while still pointing at a hub-relative guide path that existed in no repository it installed into. It loaded, referenced nothing, and degraded without an error.

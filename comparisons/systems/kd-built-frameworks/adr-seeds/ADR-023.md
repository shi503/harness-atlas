**Context.** A standards folder that only changes by pull request captures what the team already knew. It does not capture what the team learns during review, which is where most real standards originate.

**Decision.** Split the tier. **Canonical-static** changes by pull request. **Compounding-dynamic** is living memory that any review pass may append to — one file per named, reusable defect class. A class that hardens across several reviews **promotes into the static tier**. Project-level guides inherit from canon under two rules: *reference, never copy* and *tighten, never contradict*.

**Consequences.** The learning function becomes a loop with a promotion gate rather than a folder. Review effort compounds instead of evaporating.

**Failure of the simpler design.** The predecessor's loop produced 13 finding-classes and is the only running instance of this function in the entire comparison corpus. Without the compounding half, a standards tier is a document set.

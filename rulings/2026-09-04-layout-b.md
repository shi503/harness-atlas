# Ruling — Layout B, and the anchor that scrolled without opening

**Decided** 2026-09-04 on the evidence of a render check run against github.com, Chrome 152, on the
`template-v2` branch.

**The defect.** Template v2's first layout put twelve per-layer `<details>` blocks around the `####`
component headings. In that shape **a link to `#2b-hooks` scrolled to the component and left it
collapsed** — `details.open` stayed `false` both on page load with the fragment and on clicking the
matrix row's own link.

**The cause, established rather than assumed.** GitHub rewrites anchor ids to `user-content-` and runs
its own scroll handler, which bypasses the browser's native auto-expand for a target inside a closed
`<details>`. Setting `location.hash` to the prefixed id by hand *did* open it in Chrome — which
confirms the cause is GitHub's handler, not the browser, and means **no other browser rescues it.**

**The ruling.** **Headings stay outside the collapsible; only the body collapses.** Layout B: `###`
layer headings and `####` component headings in the document, each component's body inside a
`<details>` whose `<summary>` is that component's matrix mark and note.

**Verified.** The sample page loaded scrolled to `2b Hooks` with the heading visible and its body
collapsed beneath it: 33 `h4`, 33 component `<details>`, 12 layer `h3`, 4 mermaid iframes, and no
heading inside a collapsible. The mechanism is now plain heading anchors, which every renderer
honours, with no browser-specific expand behaviour relied on.

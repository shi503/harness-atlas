# Hermes Agent — Nous Research

**Why this file exists.** `[../90-short-profiles.md](../comparisons/systems/90-short-profiles.md)` §1 listed Hermes as a
harness *"named by Tan alongside OpenClaw as an always-on option for gbrain"* with a `[S]` mark — a
relayed name, never read at source. This is the source read, against the 33 components of
`[specs/v1-framework/00-README.md](../spec/v1-framework/00-README.md)`. The synthesis
across the four harnesses read this way is `[../../04-harness-alignment.md](../comparisons/04-harness-alignment.md)`.

**In one screen.** A Python harness that runs its own loop, is extended by plugins and skills rather
than by growing the core, and makes *learning* the headline: it authors skills from experience, keeps
`MEMORY.md`/`USER.md` under hard character caps, and ships a Curator that ages skills out. It is
single-tenant by declaration, mechanically bound by deny globs, a hardline blocklist and fail-closed
`pre_tool_call` hooks, and it says out loud that *"nothing inside the agent process constitutes
containment."* It ships import adapters **from** Claude Code, Codex and OpenClaw, and can hand
`openai/*` turns to the Codex app-server instead of running its own loop.

**What it does not claim.** §D below is the register. The load-bearing lines: single-tenant; no team
memory tier; no spend budget; kanban is single-host; profiles are not sandboxes.

> "The self-improving AI agent built by Nous Research. > "Hermes is a personal AI agent that runs the same agent core across a CLI, a messaging gateway (Telegram, Discord, Slack, and ~20 other platforms), a TUI, and an Electron desktop app. It learns across sessions (memory + skills), delegates to subagents, runs scheduled jobs, and drives a real terminal and browser. ### The three-question inclusion test

**1. Does state persist across sessions? — YES.** ✅

- `~/.hermes/memories/MEMORY.md` (2,200-char cap) and `~/.hermes/memories/USER.md` (1,375-char cap), Markdown, written by the agent's `memory` tool (`add`/`replace`/`remove`); "injected into the system prompt as a frozen snapshot at session start." — [https://hermes-agent.nousresearch.com/docs/user-guide/features/memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)
- `~/.hermes/state.db` — SQLite (WAL) holding session metadata, full message history, FTS5 index; `session_search` tool queries it. — [https://hermes-agent.nousresearch.com/docs/user-guide/sessions](https://hermes-agent.nousresearch.com/docs/user-guide/sessions) ; `hermes_state.py` "SessionDB — SQLite session store (FTS5 search)" — AGENTS.md
- `~/.hermes/skills/` — agent-created `SKILL.md` procedural memory. — docs/user-guide/features/skills
- Optional external memory providers (Honcho, Mem0, Hindsight, Supermemory, OpenViking, Holographic, RetainDB, ByteRover, Memori). — docs/user-guide/features/memory-providers
- Session resume: `hermes --continue`, `hermes --resume <id|name>`; goals/heartbeats persist in `SessionDB.state_meta`. — docs/user-guide/sessions, features/goals

**2. Does it serve more than one person? — Primarily ONE OPERATOR, with bounded multi-user surfaces.** ✅

- SECURITY.md: "Hermes Agent operates as a single-tenant personal agent." — [https://raw.githubusercontent.com/NousResearch/hermes-agent/main/SECURITY.md](https://raw.githubusercontent.com/NousResearch/hermes-agent/main/SECURITY.md)
- Gateway supports multiple *chat users* with a two-tier model (Admin vs Regular User) per platform scope, `allow_admin_from`, `user_allowed_commands`, DM pairing codes, `*_ALLOWED_USERS` allowlists; default deny. — docs/user-guide/messaging/ ; docs/user-guide/security
- **Managed scope** (`/etc/hermes/config.yaml`, `/etc/hermes/.env`): "lets an administrator push a baseline of configuration and secrets that a standard (non-root) user **cannot override**" — for "IT administrators managing multiple users on shared machines." — [https://hermes-agent.nousresearch.com/docs/user-guide/managed-scope](https://hermes-agent.nousresearch.com/docs/user-guide/managed-scope)
- **Profile distributions**: a git-repo package (`distribution.yaml`, `SOUL.md`, `config.yaml`, `mcp.json`, `skills/`, `cron/`) installable with `hermes profile install github.com/author/agent-name` — shares an agent *definition* across people, never memories/sessions. — docs/user-guide/profile-distributions
- Shared memory across people exists only via the Honcho provider's "multi-peer setup … workspace-level shared environment." — docs/user-guide/features/memory-providers
- No team/org/tenant object; profiles are per-machine home directories.

**3. Does it bind mechanically? — YES, several mechanical binds, with an explicit disclaimer that in-process ones are heuristics, not security boundaries.** ✅

- `approvals.deny:` fnmatch patterns in `config.yaml`, "checked case-insensitively before YOLO or approval mode settings"; a **hardline blocklist** (e.g. `rm -rf /`, fork bombs) that YOLO cannot override; `approvals.mode: smart|manual|off`. — [https://hermes-agent.nousresearch.com/docs/user-guide/security](https://hermes-agent.nousresearch.com/docs/user-guide/security)
- `pre_tool_call` hook (plugin or shell) can return `{"action":"block"}` or exit code 2; timeout "fails closed (blocks tool)". — [https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks](https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks)
- Always-blocked write paths (`~/.ssh/`, `~/.aws/`, `.env*`, `auth.json`, `mcp-tokens/`); `HERMES_WRITE_SAFE_ROOT` restricts writes to directory prefixes. — security page
- Sandboxed terminal backends (`docker` with `--cap-drop ALL`, `no-new-privileges`, PID limit; `modal`, `daytona`, `vercel_sandbox`, `singularity`, `ssh`); Docker network egress isolation. — security page; docs/security/network-egress-isolation.md
- MCP per-server `tools.include/exclude`; plugin `capabilities:` grants; plugin `mcp_allowlist`; per-platform toolsets (e.g. `hermes-webhook` restricted to 4 tools). — features/mcp, features/plugins, reference/toolsets-reference
- Disclaimer (SECURITY.md): "nothing inside the agent process constitutes containment — not the approval gate, not output redaction, not any pattern scanner." OS-level isolation is "one load-bearing security boundary."
- Prose-only layers also exist: `SOUL.md`, `AGENTS.md`/`CLAUDE.md`/`.hermes.md`/`.cursorrules`, skills, personalities.



### Harness or process layer?

- **It RUNS the loop itself**: `run_agent.py` — "AIAgent class — core conversation loop (~12k LOC)"; loop steps documented at docs/developer-guide/agent-loop (default `agent.max_turns` 500; compression at 50%). ✅
- **Adapters it ships for other harnesses:**
  - Import: `hermes import-agent claude-code` (`~/.claude`), `hermes import-agent codex` (`~/.codex`), `hermes claw migrate` (OpenClaw) — imports instructions→memory, permissions→allow/deny, MCP servers, skills. ✅ docs/user-guide/import-from-other-agents
  - Delegation skills: bundled `claude-code`, `codex`, `opencode` skills ("Delegate coding to Claude Code CLI (features, PRs)"). ✅ docs/reference/skills-catalog
  - Runtime swap: `model.openai_runtime: codex_app_server` hands `openai/*` turns to the Codex CLI app-server "instead of running its own tool loop" (loses `delegate_task`, `memory`, `session_search`, `todo`). ✅ docs/user-guide/features/codex-app-server-runtime
  - Protocols: ACP server (`hermes acp`) for VS Code/Zed/JetBrains; A2A v1.0 (JSON-RPC 2.0) client+server; MCP client and MCP server (`hermes mcp serve`); OpenAI-compatible API server on :8642. ✅
  - Shell hooks accept Claude Code's wire shape (`{"decision":"block"}`, exit code 2 — "Claude Code compatible"); `/loop` is stated as adapted from Claude Code's `/loop`. ✅ features/hooks, features/loops
- **Other systems shipping an adapter for it (as claimed in Hermes docs):** VS Code "ACP Client extension" lists "Hermes Agent" in its built-in agent list; "Buzz Desktop" auto-detects Hermes under Settings → Runtimes; Claude Code/Cursor/Codex can attach to `hermes mcp serve`. ✅ (claims on Hermes docs pages: features/acp, features/mcp) — not verified at those third parties ⚠️.

## D. Stated limitations (quoted)

- **Security posture (SECURITY.md):** "nothing inside the agent process constitutes containment — not the approval gate, not output redaction, not any pattern scanner." In-process components are "accident-prevention" heuristics; "defeating them is not a vulnerability." Out of scope: "Prompt injection without chained outcomes", "Third-party skills/plugins — boundary is operator review before install", "Public exposure without controls — operator responsibility". "No bug bounty program." — [https://raw.githubusercontent.com/NousResearch/hermes-agent/main/SECURITY.md](https://raw.githubusercontent.com/NousResearch/hermes-agent/main/SECURITY.md) ✅
- **Terminal-backend isolation** "confines shell and file operations to containers/sandboxes, but leaves Python processes (code execution, MCP, plugins) uncontained on the host." — SECURITY.md ✅
- **Profiles:** "Not a sandbox … The agent still has the same filesystem access as your user account." "Never point two agent processes at the same profile." — docs/user-guide/profiles ✅
- **Plugins:** "No sandbox: Capabilities are trust/audit layers, not isolation; plugins run as native Python." "Single active provider: Memory, context engines, and model selection allow only one active choice at a time." — features/plugins ✅
- **Managed scope (v1):** "Enforcement is filesystem permissions only"; managed `.env` "remains world-readable"; "No support for macOS/Windows native locations, signed files, or remote device management." — user-guide/managed-scope ✅
- **Kanban:** "Single-host only (PIDs are host-local, no cross-machine coordination)"; "No task linking across separate boards"; external CLI lanes "remains a design-in-progress." — features/kanban, kanban-worker-lanes ✅
- **Bot Mode:** "Live bot interruption during conversations is 'future work'"; "Cross-gateway messaging requires the Desktop to be running (unless using peer connections)"; hard caps "3 rounds and 10 messages per send." — user-guide/bot-mode ✅
- **Goals:** "Judge fallibility: The auxiliary model judge can mark goals complete prematurely or continue unnecessarily"; "Single-session scope." — features/goals ✅
- **Loops/heartbeat:** "Confined to active sessions (use cron for unattended overnight work)"; heartbeats "don't survive complete process termination." — features/loops, features/heartbeat ✅
- **MCP server mode:** "Stdio-only transport currently supported (no native HTTP server mode)"; "No claude/channel push notification protocol yet." — features/mcp ✅
- **Codex runtime:** `delegate_task`, `memory`, `session_search`, `todo` "become unavailable on this runtime." — features/codex-app-server-runtime ✅
- **Relay:** "Experimental status with potentially unstable wire contracts and configuration." — messaging/relay ✅
- **Memory caps:** "When memory exceeds limits, the tool returns an error rather than silently dropping entries." — features/memory ✅
- **Model switching:** "Mid-session model switches reset prompt caches." — configuring-models ✅
- **Subagent lifecycle API:** "Results persist in-process for one hour; after restart, reconnection becomes unavailable." — developer-guide/subagent-lifecycle-api ✅
- **Distributions:** "Distributions are unsigned by default—trust relies on the author and git host." — profile-distributions ✅
- **Webhooks:** "HMAC validates the *sender*, not the *content*"; "Per-route toolsets are manual config edits only—agents cannot self-grant elevated tools." — messaging/webhooks ✅
- **Model floor:** "Hermes Agent requires a model with at least 64,000 tokens of context." — getting-started/quickstart ✅
- **Contribution rubric (AGENTS.md):** "extended primarily through plugins and skills, not by growing the core"; "A plugin that needs to edit core files is a design smell." — AGENTS.md; developer-guide/codebase-ownership ✅

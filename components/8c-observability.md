### 8c · Observability

**Layer 8 Trust** · function `F11 (split)` · job `J8`

> **What did it actually do?**
>
> Observability is **the Trace** — the reconstructable sequence of what an agent did, step by step,
> **without asking it what it did**. Its defining property is independence from the narrator: the
> record is emitted by the harness, not summarised by the thing being observed.

**Not asking the agent is the whole distinction, and it is cheap to lose.** An agent's own account of
its run is generated by the same process that produced the run, and *"the context that produced a
diff already believes it is correct"*
([`systems/qm.md`](../comparisons/systems/qm.md); originally argued in `loomwarp-team-system` `specs/v1/04-benchmark-qm.md`, private — risk-scaled adversarial
review). A trace assembled from the agent's summary is not a weaker trace; it is a different artifact
with the same failure mode as the work it describes.

**`F11 Instrumentation` split across two layers, and this is the half that stayed in Trust.** The
Trace is a Trust concern — *can this be believed* — while the Accounting is
[`8d`](./8d-efficiency.md) and the Constraint is
[`9f`](./9f-diagnose-the-bottleneck.md), which acts on the harness rather than on a unit of
work. **The crossing is the point**: `J17` states its own maturity gate, *"it depends on rituals and
on `J12`"*, and a function whose parts depend on each other across an ordering boundary is not one
gradeable row ([`CROSSWALK.md`](../spec/v1-framework/CROSSWALK.md) §2).

**The gradeable property is reconstruction, not volume.** Logs accumulate by default; a trace has to
be assembled. What separates the two is whether the **agent tree** can be rebuilt — parent to child,
across delegation — from what was emitted, which is a schema decision made before the first run and
essentially impossible to retrofit onto a log that did not carry the keys.

**What this layer is not.** It is not [`8b`](./8b-evidence.md) Evidence — a trace shows the
**steps**, a ledger holds the **claims**, and the two fail apart: a team can watch every tool call of
a unit of work whose completion nobody recorded, and can hold immaculate handoff records over runs
nobody can replay. It is not `8d`, which reads the same stream for **cost** rather than for sequence.

**How do we work?** *"We can see what an agent did, step by step, after the fact, without asking it what it did."*

| **LoomWarp** | `◐` — a structured event stream exists and the agent tree does not. **Horizon:** `shipped` — `03-jtbd.md` §2 `J8` *"Who"* and *"Corpus"* — `trace` 65 · `audit` 39; Claude Code ships OTel metrics, events and spans, Gas City ships the Event Stream

**The consequence.** This is the most-shipped row in Trust and the one teams most often adopt without
deciding anything, because the vendor turns it on. **What that leaves is visibility without a
question**: a stream nobody reads, a tree nobody reconstructs, and — because the accounting and the
constraint were split off into rows of their own — no automatic path from *we can see everything* to
*we know what to fix.*
